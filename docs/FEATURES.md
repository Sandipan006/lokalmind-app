# LokalMind v2 — Feature Showcase

Every differentiating capability of LokalMind, explained end-to-end. These are the features that make LokalMind different from every other AI app.

---

## 1. On-Device LLM — Download & Run Locally

**The core promise**: every inference runs on your device. No API key, no subscription, no data leaving the phone.

### How it works

1. User opens the app for the first time → onboarding Step 3 detects device RAM via `react-native-device-info`
2. App recommends the best model that fits within 60% of available RAM (e.g. iPhone 13 with 4GB RAM → recommends Qwen 3.5 2B)
3. User taps Download → `DownloadModelUseCase` fetches the GGUF file from Hetzner CDN via `expo-file-system`
4. Download runs in the background with real-time progress, speed (MB/s), and ETA shown inline
5. On completion, model metadata saved to `models:downloaded` in AsyncStorage
6. First chat → `EnsureModelLoadedUseCase` calls `ILLMEngine.initialize()` → `llamaRnAdapter` loads the GGUF into memory via `llama.rn`
7. All subsequent inference is fully on-device via Metal (iOS GPU acceleration)

### Model lineup

| Model | Size | Best for |
|---|---|---|
| Qwen 3.5 0.8B Q4 | ~500 MB | Fast responses, low-RAM devices, quick tasks |
| Qwen 3.5 2B Q4 | ~1.2 GB | Balanced quality + speed, everyday use |
| Qwen 3.5 4B Q4_K_M | ~2.5 GB | High quality, complex reasoning, writing |
| Gemma 3 4B Q4_K_M | ~2.5 GB | Coding, structured tasks, analytical queries |
| DeepSeek R1 1.5B Q4 | ~900 MB | Step-by-step reasoning, math, logic chains |

### Resumable Downloads

Downloads survive interruptions. If the app is backgrounded, the connection drops, or the user pauses manually:

- `PauseDownloadUseCase` saves the byte offset to AsyncStorage
- `ResumeDownloadUseCase` restarts from the saved offset using HTTP Range requests
- Progress bar picks up exactly where it left off

## 2. Streaming Chat with Token-by-Token Rendering

Responses appear word-by-word as the model generates, not as a single block after a long wait.

### How it works

1. `ILLMEngine.generateResponse()` accepts an `onToken` callback
2. `llamaRnAdapter` calls `onToken(token)` for each token as it is generated by `llama.rn`
3. `ChatViewModel.appendToStreamingResponse(token)` accumulates the token into the current AI message
4. A **debounced flush** batches token updates and flushes to the UI every ~50ms — prevents 60fps render bottleneck on fast models
5. A blinking typing cursor `▌` is shown at the end of the streaming message until generation completes
6. `FinalizeMessageUseCase` persists the complete response to SQLite once streaming ends

### FlashList

The message list uses `@shopify/flash-list` for virtualized rendering. Reverse-scrolling (newest at bottom). Auto-scrolls to bottom on new tokens during streaming.

**Phase**: 1 (streaming), 2 (full UI)

## 3. Message Queue

No message is ever dropped, even if you send multiple messages while the model is generating.

### How it works

- `ChatViewModel.messageQueue` is an observable array
- User taps Send while `isGenerating = true` → message pushed to `messageQueue`
- `FinalizeMessageUseCase` sets `isGenerating = false` → `ChatViewModel` drains the queue, processing the next message immediately
- Queue is in-memory only (not persisted across restarts)
- **Max depth: 10** — if exceeded, input bar shows "Please wait…" nudge
- Input bar badge shows pending count in real time (e.g. `2 queued`)

**Phase**: 1

## 4. Reply to Message

Swipe right on any message (user or AI) to quote it. The model understands exactly what you're responding to.

### How it works

1. User swipes right on any message bubble → `react-native-gesture-handler` triggers `ChatViewModel.setReplyTarget(message)`
2. Input bar renders a **quoted bubble preview** above the text field — shows the first 80 chars of the quoted message, dismissible via ✕
3. User types their response and taps Send
4. `SendMessageUseCase` persists `replyToId` in the `messages` table
5. `BuildPromptUseCase` injects the quoted message into the AI context:
   ```
   [Replying to: "The time complexity of quicksort is O(n log n) on average"]
   Can you explain why it degrades to O(n²) in the worst case?
   ```
6. AI responds with full awareness of which prior message is being addressed
7. Message bubble renders with a visual reply thread indicator linking back to the original

**Phase**: 2

## 5. Per-Session System Prompt

Every chat session can have its own custom system prompt, completely independent of the global prompt.

### How it works

- User taps `···` in the chat header → opens per-session system prompt editor (plain text field)
- Prompt saved to `chats.sessionPrompt` column in SQLite (tied to this specific chat)
- `ResolveSystemPromptUseCase` checks `sessionPrompt` first — it wins over the global prompt and mode defaults
- Editing or clearing the session prompt takes effect on the next message send
- Session prompt is shown as a badge in the chat header when active

### Priority chain

```
Per-session prompt  →  Global custom prompt  →  Mode default prompt
(highest priority)                              (fallback)
```

**Phase**: 2

## 6. Global Custom System Prompt

A single system prompt applied to every new chat by default. Set it once, forget it.

### How it works

- User goes to Profile → AI Behavior → taps the global system prompt field
- Plain text editor, saved on dismiss to `settings:globalSystemPrompt` in AsyncStorage
- Applied to every chat where no per-session prompt is set
- Can be cleared at any time — falls back to the active mode's default prompt
- Shown as a subtle indicator in the chat header when active

**Phase**: 3

## 7. AI Modes

Four pre-built prompt modes that change how the AI behaves. Each has a default system prompt the user can override.

| Mode | Behaviour |
|---|---|
| **General** | Helpful, concise, conversational. Default for most users. |
| **Coding** | Code-first. Prefers code blocks. Explains technical concepts precisely. Structured output. |
| **Creative** | Open-ended, imaginative. Storytelling, brainstorming, writing. Less constrained. |
| **Marketing** | Conversion-focused. Messaging, positioning, hooks, CTA, campaign-ready copy. |

### How it works

- Mode selector shown inside the chat input box
- Active mode stored in `ChatViewModel.selectedMode`
- `ResolveSystemPromptUseCase` uses the mode's default prompt as the lowest-priority fallback
- User can override any mode's default prompt in Profile → AI Behavior → tap the mode
- Override stored at `settings:mode:{modeName}:systemPrompt` in AsyncStorage
- Each mode's override can be reset to default independently

**Phase**: 3

## 8. Persistent Global Memory

LokalMind remembers facts about you across all conversations. The AI gets smarter about you over time — without any cloud.

### How it works

Every chat turn, before the AI responds:

1. `GetMemoryFactsUseCase` loads all facts from the `memory_facts` SQLite table
2. Facts injected into the system prompt as a `[Memory]` block:
   ```
   [Memory]
   - User is a React Native developer
   - User prefers concise answers without filler text
   - User is learning TypeScript
   - User's name is Sandipan
   ```
3. The AI reads these facts and responds accordingly — no need to re-explain yourself every session

### Auto Memory Extraction

After every 5 user messages, the LLM silently reviews the exchange and extracts new facts:

1. `MemoryExtractionUseCase.maybeTrigger(chatId)` — runs a second LLM inference in the background (non-blocking)
2. Extraction prompt asks the model to return new facts as a JSON array
3. Each new fact is semantically deduplicated before saving — no duplicates
4. New facts saved to `memory_facts` with `sourceChatId` and timestamp
5. A subtle **"Memory updated"** toast appears in the chat — non-blocking, does not interrupt the conversation

### Memory Management (Profile → Memory)

- View all stored facts as a list, each showing its source chat
- Tap any fact to edit it
- Swipe to delete individual facts
- **Add fact manually** — user can add their own facts (stored with `isManual = 1`, never auto-deleted)
- **Clear all memory** — destructive action with confirmation dialog

### Privacy Controls

- Global toggle: `settings:memoryEnabled = false` → memory never injected, extraction never runs
- Per-session disable: turn off memory for a specific chat
- All memory is local SQLite — never leaves the device

**Phase**: 3

## 9. Voice Input (Whisper STT)

Hold-to-record voice input. On-device transcription via `whisper.rn`. No audio leaves the device.

### How it works

1. User holds the mic button in the input bar
2. `expo-av` begins recording to a temp `.wav` file
3. Animated waveform visualizer gives real-time feedback while recording
4. User releases → recording stops → `TranscribeAudioUseCase` runs
5. `IWhisperEngine.transcribe()` processes the `.wav` on-device via `whisper.rn`
6. Transcribed text inserted into the input bar in **editable state** — not auto-sent
7. User reviews, corrects if needed, then taps Send
8. Temp `.wav` deleted immediately after transcription

### Whisper Model

- **Whisper Base** — 142 MB `.bin` file
- 99 languages, auto language detection (no configuration needed)
- Supports: English, Hindi, Tamil, Telugu, Bengali, Kannada, Marathi, Gujarati, and 91 more
- Downloaded separately from GGUF models, shown in Model Management screen

### Edge Cases

- Mic button shows a download prompt if Whisper model is not yet downloaded
- Tap ✕ to cancel recording at any time — temp file deleted, no transcription
- Transcription error → error toast, input bar cleared

**Phase**: 3

## 10. Model Switching

Switch the active model at any time — between chats or mid-session.

### How it works

- Tap the model name in the chat header → model switcher bottom sheet
- Shows all downloaded models with their size and a "Best for" tag
- Selecting a new model calls `SetActiveModelUseCase`:
  1. `ILLMEngine.unloadModel()` — releases the current model from memory
  2. `models:active` updated in AsyncStorage
  3. Next message send triggers `EnsureModelLoadedUseCase` → loads the new model
- Active model badge shown persistently in the chat header

**Phase**: 1

## 11. Chat History

All conversations are persisted in SQLite and resumable at any time.

### How it works

- Every chat session has a row in the `chats` table with `id`, `title`, `lastMessage`, `timestamp`, `modelId`, `mode`
- Every message has a row in the `messages` table with full text, timestamp, and optional `imagePath` / `replyToId`
- Chat list in the sidebar shows all sessions sorted by `timestamp` descending
- Tapping any session loads its messages via `GetChatsUseCase` + `GetMessagesUseCase`
- Chat title auto-generated from the first user message (truncated to 40 chars)

### Chat Management

- **Rename**: tap the chat title in the header → inline edit
- **Delete**: swipe left on any chat in the sidebar → confirm delete
- **Clear messages**: `···` menu → Clear Chat (keeps the session, deletes all messages)
- **New chat**: button at the top of the sidebar → creates a new `chats` row

**Phase**: 2

## 12. Image Input (Vision)

Attach a photo to any message for vision-capable models.

### How it works

- Paperclip icon in the input bar → picker: Camera or Photo Library
- Selected image stored as a local file URI in `ChatViewModel.pendingImagePath`
- Image preview shown above the input bar (dismissible)
- On send, `imagePath` persisted in the `messages` table
- `BuildPromptUseCase` attaches the image path to the `LLMMessage` for vision models
- `llamaRnAdapter` passes the image to `llama.rn`'s multimodal context

**Phase**: 2

## 13. Code Blocks & Markdown

AI responses render with full markdown support and syntax-highlighted, copyable code blocks.

### How it works

- AI response text parsed for markdown syntax
- Code blocks rendered with syntax highlighting (language auto-detected from fence tag)
- **Copy button** on every code block — copies raw code to clipboard
- Inline code, bold, italic, headers, bullet lists, numbered lists all rendered correctly
- Streaming tokens are parsed incrementally — markdown renders progressively as tokens arrive

## 14. Message Actions

Long-press any message to access contextual actions.

| Action | Available on |
|---|---|
| Copy text | User + AI messages |
| Regenerate response | AI messages only |
| Delete message | User + AI messages |
| Reply | User + AI messages |

**Regenerate**: deletes the AI message and re-runs the generation pipeline from the preceding user message.
